# Skill Evaluation Framework (agentskills.io Specification)

This document describes the evaluation framework implemented in this repository, conforming to the open [agentskills.io Evaluating Skills specification](https://agentskills.io/skill-creation/evaluating-skills.md).

---

## 1. Overview & Purpose

Skills are domain instructions and architectural constraints for AI coding agents. Evaluating a skill provides quantitative, empirical proof that:
1. **Triggering Accuracy:** The skill activates appropriately when relevant tasks are prompted.
2. **Behavioral Integrity:** The agent enforces mandatory rules (e.g., Power of 10 safety constraints, typing protocols, seed reproducibility, boundary validation).
3. **Comparative Uplift:** Outputs produced **with** the skill demonstrably outperform outputs produced **without** the skill (baseline) in accuracy, structure, and safety.

---

## 2. Directory Structure & File Schema

Evaluation suites reside directly within each skill folder under `skills/<skill-name>/evals/`:

```
skills/<skill-name>/
├── SKILL.md
├── references/
└── evals/
    └── evals.json          # Test cases and assertions
```

### `evals.json` Specification

```json
{
  "skill_name": "python-developer",
  "evals": [
    {
      "id": 1,
      "prompt": "Implement an iterative graph DFS traversal function with hard loop bounds and slots domain model.",
      "expected_output": "A Python module containing a GraphNode dataclass with __slots__, an iterative DFS implementation with hard loop bounds, and no recursive calls.",
      "files": [],
      "assertions": [
        "The graph node domain model uses @dataclass(slots=True) or explicit __slots__",
        "The DFS algorithm is implemented iteratively using an explicit stack",
        "The algorithm contains zero recursive function calls",
        "The while loop has a hard maximum iteration bound to prevent infinite loops",
        "All functions include strict Python type annotations"
      ]
    }
  ]
}
```

### Field Definitions

| Field | Type | Description |
|---|---|---|
| `skill_name` | `string` | Must match the exact directory name of the skill. |
| `evals` | `array[object]` | List of 2 to 5 representative, real-world evaluation test cases. |
| `id` | `integer` | Unique positive integer identifier for the test case. |
| `prompt` | `string` | Realistic user prompt that should trigger and exercise the skill. |
| `expected_output` | `string` | Description of the expected high-integrity output. |
| `files` | `array[string]` | Optional relative paths to input fixtures or initial files. |
| `assertions` | `array[string]` | Objective, verifiable criteria graded as PASS or FAIL. |

---

## 3. Writing Effective Assertions

Assertions must be specific, falsifiable criteria rather than subjective impressions:

### ✅ Good Assertions (Verifiable & Distinct)
- *"The domain entity defines `__slots__` or uses `@dataclass(slots=True)`"*
- *"The repository port inherits from `typing.Protocol`"*
- *"Contains zero recursive calls; uses an explicit stack"*
- *"Every while loop includes a maximum iteration safety guard"*
- *"Environment reset calls `super().reset(seed=seed)`"*

### ❌ Weak Assertions (Vague & Ambiguous)
- *"Code is high quality and clean"*
- *"Follows good Python style"*
- *"Works as expected"*

## 4. Evaluation Workspace & Benchmark Aggregation

During an evaluation run (or A/B test), execution artifacts are captured in a structured workspace:

```
evals-workspace/
└── iteration-1/
    ├── eval-1/
    │   ├── with_skill/
    │   │   ├── outputs/        # Generated files
    │   │   ├── assertions.json # Evaluated assertions
    │   │   ├── grading.json    # Graded results & pass rate
    │   │   └── timing.json     # Duration ms & token count
    │   └── without_skill/
    │       ├── outputs/
    │       ├── assertions.json
    │       ├── grading.json
    │       └── timing.json
    ├── benchmark.json          # Aggregated mean, stddev, and deltas
    └── feedback.json           # Qualitative human review notes
```

### Benchmark Metrics & Delta Uplift

The `benchmark` command aggregates results across all evaluation cases in the iteration:
- **`pass_rate`:** Mean assertion success rate.
- **`time_seconds`:** Execution time in seconds.
- **`tokens`:** Token usage.
- **`delta`:** Uplift calculated as `with_skill - without_skill`.

Example summary output generated by `skills/skill-evaluator/scripts/eval_skill.py report`:

```markdown
# Skill Evaluation Benchmark Report
**Iteration Directory:** `iteration-1`

| Metric | Without Skill (Baseline) | With Skill | Delta (Uplift) |
|---|---|---|---|
| **Pass Rate** | 42.5% | 95.0% | **+52.5%** |
| **Execution Time** | 22.4s | 18.2s | -4.2s |
| **Token Usage** | 3,450 | 2,820 | -630 |
```

## 5. Tooling & CLI Commands

The repository provides `skills/skill-evaluator/scripts/eval_skill.py` and `just` integration recipes:

### 1. Validate Evaluation Suites
Validate that all `evals/evals.json` files conform strictly to the schema:
```bash
just lint-evals
# Or directly:
python skills/skill-evaluator/scripts/eval_skill.py validate --all
python skills/skill-evaluator/scripts/eval_skill.py validate python-developer
```

### 2. Scaffold a New Evaluation Suite
Create a compliant starter `evals/evals.json` for any skill:
```bash
just scaffold-evals data-engineer
# Or directly:
python skills/skill-evaluator/scripts/eval_skill.py scaffold data-engineer
```

### 3. Grade an Evaluation Run
Grade outputs in a test execution folder against assertions:
```bash
python skills/skill-evaluator/scripts/eval_skill.py grade --eval-dir evals-workspace/iteration-1/eval-1/with_skill
```

### 4. Aggregate Benchmarks & Uplift Report
Aggregate test run outputs across an iteration and display the markdown comparison table:
```bash
just benchmark-evals evals-workspace/iteration-1
just report-evals evals-workspace/iteration-1
```
